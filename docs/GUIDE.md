# 详细说明

> 早期的使用和实现说明，按功能陆续追加，信息比首页 README 更细。部分段落里的测试数字和限制是当时的状态。

Windows 独立截屏与录屏工具。入口：`artifacts/ThorCapture.exe`。

这是独立项目，构建和运行不依赖原来的 Mistria 项目。

## 项目结构

- `src/`：源码。`ThorCapture.cs` ADB 与截图；`Recording.cs` 录屏；`MainForm.cs` 主窗口；`Preview.cs` 预览区；`DeviceArt.cs` Thor 外壳绘制与配色；`Controls.cs` 深色主题与自绘控件。
- `backups/before-ui-redesign-20260926/`：界面重做前的源码与 EXE。
- `artifacts/thor-capture-settings.txt`：外壳配色、预览模式、侧栏宽度、保存位置等设置（旧的 `capture-folder.txt` 仍可读取）。
- `tests/`：模拟 ADB 与可选实机回归。
- `tools/`：构建和测试脚本。
- `artifacts/ThorCapture.exe`：独立程序。
- `artifacts/captures/`：图库，已复制原目录的 119 张截图；新截图默认保存于此。
- `artifacts/adb-path.txt`：本机 ADB 路径配置，不嵌入源码。
- `evidence/prior-verification/`：拆分前的真实截图、视频和验证记录，JSON 中原路径保留作为历史来源。
- `evidence/thor-capture-tests/`：独立项目运行回归后生成的结果。

原项目及原图库保留不动，两个图库此后不会自动同步。ADB 属于 Android SDK 外部依赖；换电脑时修改 `adb-path.txt`，或将 platform-tools 放在 EXE 旁。

## 使用

- 连接 USB，在 Thor 上允许 USB 调试。顶栏左侧的设备按钮显示连接状态（绿点已连接），点击可切换设备或重新检测。上下屏通过 dumpsys 的物理显示 ID 获取；下屏逻辑 ID 可以变化。
- 顶栏选择「上屏 / 下屏 / 双屏」，按 F5 或「截图」。双屏逐屏截图，同批图片共用组名，预览自动配对；它不是同一时刻的同步采样。
- 预览区三种模式（数字键 1/2/3）：「带壳」把截图放进 Thor 正面外壳，自动配对同组的另一块屏；「单图」适应窗口，放大时按整数倍、最近邻；「1:1」原始像素，可拖动或滚轮平移。
- 「带壳」模式支持鼠标演示：左键按住 ABXY、系统键或底部 L1/L2/R2/R1 提示条；按住十字键并拖动可切换方向/斜向；拖动摇杆可演示偏转，右键按住摇杆演示 L3/R3。松开、失焦或切换视图自动释放。无需连接设备，仅演示外壳动画，不控制 Thor，也不写入录屏的按键时间线。
- 外壳按 AYN 官方四种配色绘制：黑色（青色摇杆灯）、白色、彩虹（SNES 配色 ABXY）、透明紫（颜色取自实机照片：透明按键区与铰链可见内部结构，深灰按键，灯效默认关闭）。比例依照实机正面：上屏 16:9（1920×1080），下屏 1240×1080，左摇杆在十字键上方，ABXY 在右摇杆上方。这是程序绘制的示意图，并非官方产品照片。
- 「导出带壳图」（Ctrl+E）导出透明背景 PNG，上屏按 1920 像素原尺寸绘制（整图约 2340×2820）；Ctrl+Shift+C 复制带壳图（浅色背景，剪贴板不保留透明）。原始截图不受影响。
- 图库按日期分组，支持全部/上屏/下屏/视频筛选、文件名或日期搜索（Ctrl+F），Ctrl/Shift 多选、方向键浏览、右键菜单，Del 移入回收站。🔗 标记表示有同组的另一块屏。视频缩略图来自 Windows 缩略图缓存。图片双击/Enter 用系统查看器打开；视频使用内置播放/暂停。
- Ctrl+C 复制当前图片，Ctrl+S 另存为。底栏可打开或更改保存位置，并会记住；不会搬走旧目录中的文件。
- 录屏可选择「上屏 / 下屏 / 双屏」，点击「录屏」或按 F6。双屏会并行启动两路录制，再次点击统一停止；两段 MP4 共用批次号，图库自动显示配对标记。

## 录屏范围

采用设备自带 `screenrecord --display-id` 保存画面，每屏 H.264 / MP4、8 Mbps、原生分辨率，每次最长 180 秒后自动保存。工具栏「声音：系统」默认采集游戏/媒体声音并保留 Thor 外放，可点击关闭；有声模式需要 Android 13+、附带的固定 scrcpy 音频组件及 FFmpeg/ffprobe，不采集麦克风。双屏只采集一份声音，写入两段原片，也可导出一个双屏带壳有声 MP4。声音采集或合成失败明确提示并保留画面和可恢复声音。旧无声视频无法补回声音，应用限制仍可能导致声音无法捕获。说明见 [录屏声音](RECORDING-AUDIO.md)。两路视频并发启动和停止，尚不保证帧精确同步；实际声音捕获、漂移和双编码器支持仍待实机确认。单侧失败保留成功原片、设备文件及未完成下载。

## 实机按键反馈与视频导出

### 内置视频回看

选中同组任意一屏 MP4，即可像双屏截图一样在「带壳」模式中查看两屏。选中后显示首帧，点击底部「播放」、双击/Enter 或按空格播放/暂停；拖动进度条同时跳转两屏，结束后可重播。「单图」和「1:1」显示选中的那一屏。上下屏共用回放时间轴，截至较短原片结束；这不会消除原始录制的启动偏差。

右上角按钮自动切换为「导出带壳视频」，也可使用底部「导出视频」、Ctrl+E 或「视频导出…」。选择「双屏带壳视频」得到一个同时显示上下屏的 MP4，或者分别复制两段原片。若存在 `.input.csv`，回看与导出均读取操作记录；只存在另一屏旁的时间线也会使用。鼠标演示不写入记录、不进入视频导出。

内置回放依赖已有 FFmpeg/ffprobe，Windows waveOut 输出音频；解码预览最大 960×540/屏，30fps 取样，原片不变。「1:1」在视频中指解码预览像素，视频导出仍使用原片。有声原片在内置回放和带壳导出中保留声音，双屏只播放一份。播放/暂停和跳转同步控制音频，状态区显示有声/无音轨。缺依赖或视频损坏会显示原因，不自动跳出外部播放器。

进度跳转会替换旧解码任务；切换素材、启动设备录屏、删除或关闭窗口时释放本次播放器和文件。设备操作/视频合成期间暂停回放，完成后保持暂停。轨道偏移、逐帧步进和片段剪辑尚未加入。

### 输入与导出步骤

1. 连接设备后点击「按键反馈」，通过 ADB `getevent` 只读游戏手柄事件。请先松开全部按钮，再用「按键校准」核对 A/B/X/Y、肩键、摇杆按压和右摇杆轴；映射按设备保存。不支持读取时会显示原因，不会自动 root 或提权。
2. 外壳实时显示按压、十字键方向、双摇杆偏移和 L3/R3；正面看不到的肩键使用外壳下方提示条。十字键围绕中心支点倾斜，支持斜向按压、边缘厚度和松开复位；ABXY 使用下陷和阴影反馈。可同时打开「实时预览」查看双屏；截图时画面取景暂停；录屏期间自动连续截图取景，按键反馈继续。
3. 开启反馈后录屏，会在 MP4 旁保存同名 `.input.csv` 操作时间线。双屏共享同一时间原点，并在两段原片旁各保存一份。请保留时间线；这是输入记录，不会向设备发送或回放操作。输入断开时复位并标记时间线不完整。
4. 图库选中视频，点击「视频导出…」，选择原片或带壳视频。成对双屏会分别复制两段原片，或合成一个同时显示双屏的带壳视频（截至较短视频结束）。带壳导出使用当前配色，900×1120、30 fps；单屏原片的另一屏显示占位。没有时间线的旧片可导出静态外壳。
5. 按键采用电脑收到事件的时间，视频开始存在 ADB 启动延迟；不是帧精确同步。可调整 ±5000 毫秒偏移，正数让动画延后。原始 MP4 保留，取消合成不会发布未完成视频。

视频流预览需要 FFmpeg；视频合成另需同目录 ffprobe。查找顺序：`THOR_FFMPEG` 环境变量、EXE 旁 `ffmpeg.exe`、`ffmpeg-path.txt` 中的完整路径。本机配置使用已存在的 FFmpeg，没有新增安装。没有 FFmpeg 或设备视频流不可用时，预览会明确提示并回退到截图模式。

截图同时尝试读取各屏前台应用，保存 `.png.thor-meta.txt` 旁路信息；图库支持包名/别名搜索，右键可设置应用别名。读取不到时明确标记未知，不影响截图。

本次实现的本机回归覆盖输入解析、校准、丢包复位、时间线、前台应用元数据及原有截图录屏流程。历史视频配合**模拟按键**已完成带壳合成及逐帧解码；尚未验证 Thor 实机输入权限、真实映射、实际同步误差和长时间稳定性。

### 预览性能更新

预览改为两路持续 H.264 视频流，设备编码后经 ADB 管道传输、FFmpeg 解码，不再为每帧重启截图命令。预览默认按原比例缩至最大 960×540（Thor 上屏 960×540，下屏 620×540），每路 3 Mbps；「预览设置」可调整高度上限、每屏码率、电脑显示帧率上限、预览屏幕，以及原生 PNG 取景；原始截图及录屏分辨率不受影响。每屏仅保留一个待显示的最新帧，更新互不等待；画面、静态外壳、按键分别绘制，画面刷新不再重算外壳和静止的灯光。

状态栏分别显示上下屏的解码接收 fps 与送显 fps（交给预览区的频率），静态画面可能停止产生新帧；这些数值不是端到端延迟或实际绘制 fps。按键动画由预览区独立调度，按实际经过时间平滑推进偏转和按压力度，静止后停止刷新。普通视频取景占用设备编码器，截图、录屏和合成前会释放；录屏期间自动切换连续截图取景，录像结束后恢复此前的预览意图；停止预览或关闭窗口时清理本次进程。旧 Android 的视频流到 180 秒正常结束后自动重连，可能短暂断帧。

本轮将按键拆成可复用的部件缓存：十字键动时不重算两侧摇杆和灯光，画面刷新只请求屏幕区域。摇杆网格与环形灯光计算复用不变的角度数据，保留立体结构、齿纹和反射。同机 CPU 离屏绘制测量：760×940 预览区十字键场景平均约 22.4→4.4ms，双摇杆场景约 22.4→13.2ms。大窗口双摇杆仍约 26.3ms，不能据此承诺 60fps。方法、P95 与限制见 [动画性能记录](ANIMATION-PERFORMANCE.md)。

断流、编码器拒绝或缺少 FFmpeg 时，明确标记「兼容截图预览」并回退至所选屏幕的并行抓图（快速原始像素优先，不支持则PNG），遵守尺寸上限。再次开启预览会重新尝试视频流。本机回归与真实 FFmpeg 的合成视频流检查已通过；Thor 的两路编码器支持、实际帧率、输入到画面的延迟及长时间稳定性仍待实机验收，未声称达到 30/60fps 或低于 300ms。

H.264 标准输出机制依据 [Android screenrecord 源码](https://android.googlesource.com/platform/frameworks/av/+/refs/heads/main/cmds/screenrecord/screenrecord.cpp)。本机检查证据见 `evidence/dual-recording-regression.txt` 和 `evidence/stream-regression.txt`；合成测试使用彩色测试视频与模拟 ADB，不是 Thor 实测。

原始像素格式依据 [Android screencap 源码](https://android.googlesource.com/platform/frameworks/base/+/master/cmds/screencap/screencap.cpp)；支持 12/16 字节头和 RGBA/RGBX/BGRA，未知或广色域格式回退 PNG。

停止时只向本次独立进程发送 SIGINT，让编码器完成文件；不会 killall。设备文件使用唯一名称。下载先写入 `.partial`，检查 MP4 顶层结构包含 ftyp/moov/mdat 后改名。此校验不等于逐帧解码。

失败时保留设备端原文件，并在错误框显示路径；本地 `.partial` 也保留供排查。重新连接后可用 `adb -s SERIAL pull DEVICE_PATH LOCAL_PATH` 恢复。录制或设备命令运行时暂不允许关闭窗口，等待停止/保存或超时结束。

ADB 查找：THOR_ADB、程序同目录 adb.exe / platform-tools、Android SDK 环境变量、adb-path.txt、当前用户默认 Android SDK 路径，最后尝试 PATH。无设备时仍可浏览图库。

预览调参说明见 [预览参数与延迟](PREVIEW-TUNING.md)。本轮增加即时管道刷新和限帧节拍检查；可选原生高画质与 PNG，但 H.264 不承诺无损，电脑限帧不控制设备编码帧率。179项离线检查通过，没有新增实机测试。

录屏期间现在自动持续取景，可暂停/恢复显示；取景错误不停止原片录制。录屏取景暂用不占额外视频编码器的连续截图，帧率低于普通视频流，不承诺高帧率共享采集。详见 [录屏期间取景](RECORDING-PREVIEW.md)。本批193项离线检查通过，实机并发帧率与对录像的影响尚未验证。

## 构建和回归

```powershell
./tools/build-capture-tool.ps1
./tools/test-capture-tool.ps1
# 合成 H.264 流、窗口回退与恢复、双屏带壳导出检查，不连接实机
./tools/test-capture-tool.ps1 -Stream
# 固定模拟姿态的 CPU 绘制测量，不连接设备
./tools/measure-animation.ps1
# 经用户同意后实机验证：单屏/双屏短录制及 12 秒视频流接收采样
# 帧率采样需要正在变化的游戏画面，端到端延迟需另行对照实机
./tools/test-capture-tool.ps1 -Live
```

使用 Windows 内置 .NET Framework C# 编译器，无需安装额外运行时。
