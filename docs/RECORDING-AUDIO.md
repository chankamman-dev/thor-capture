# 录屏系统声音

2026-09-27：原有 Android `screenrecord` 原片没有声音，内置播放器也没有声音输出。本批加入独立的系统音频采集、MP4 合成、内置音频输出与带壳导出保留音轨。开发和回归均为离线；没有连接 Thor。

## 使用

1. 重启更新后的 Thor Capture，保留程序旁的 `scrcpy-server-v3.3.4` 与第三方许可证目录。
2. 工具栏「声音：系统」默认开启。点击可切换「声音：关」，下次录制生效；录制期间禁止更改。
3. 选择上屏、下屏或双屏后录屏。声音来自设备的游戏/媒体播放，不来自电脑或设备麦克风。设备外放保留；录屏连续取景保持原有方式。
4. 停止后先保存画面，再将 AAC 192 kbps / 48 kHz / 双声道声音写入 MP4。视频使用流复制，保持原始视频编码数据。双屏采集一次，共享声音写入两段原片。
5. 图库内置播放和带壳导出从所选原片读取一份声音；所选原片无音轨时尝试配对原片。双屏声音不混叠。播放器状态区显示「有声」或「无音轨」。

以前的无声录屏缺少声音数据，更新无法补回。无声模式不需要声音组件，也不影响旧 MP4、PNG 和 CSV。

## 条件与失败处理

- 系统声音模式要求 Android 13+、已授权的 ADB、既有 FFmpeg/ffprobe，以及匹配固定 SHA256 的音频组件。缺少条件时阻止有声录制并提示原因，可主动切换无声模式；不会静默生成无声成品冒充成功。
- 使用 scrcpy 的 playback + audio_dup，保留本机播放。某些应用禁止播放捕获，受保护内容或非媒体声音不保证可采集。用户须保证应用有声音并且设备未静音；成功采集静音 PCM 并不代表应用有可捕获声音。
- 启动声音通道后再启动所选视频编码器。启动失败不启动视频。录制中音频断开不停止画面录制；结束时提示音频失败，保留可恢复 WAV 和视频。
- 声音合成使用唯一 `.partial.mp4`，校验 MP4 与音轨后原子替换原片。失败保留原视频和 WAV，删除未完成合成文件；双屏一侧成功合成、另一侧失败时明确提示未全部完成。
- 声音组件临时上传到 `/data/local/tmp/thor-audio-{唯一ID}.jar`，运行于 ADB shell，不安装 APK、不提权、不启用控制或麦克风。停止关闭 socket，按 PID、启动时刻、服务器名与会话 ID 验证后清理自己拥有的进程，只移除本次 forward 和临时文件。断线可能留下唯一命名的设备临时文件。
- 内置播放采用 Windows waveOut，最多提交一个约 20 ms PCM 块。音视频使用同一个播放时钟；暂停暂停音频输出，跳转清空旧音频并重启解码，关闭等待解码与输出释放。无法打开电脑音频设备时显示原因，画面仍可播放。

## 同步与验收边界

音频 socket 使用 scrcpy PCM 数据包时间戳（48 kHz / 16-bit / 双声道），缺块按时间戳补静音，明显时间跳变中止音频采集。视频启动前的音频按本机单调时间估计裁掉，音轨补齐至各原片的视频时长，不截短视频。原生双屏编码器启动不保证逐帧同步，音频第一块到达仍含传输延迟；这不是实机精确同步证明，也没有承诺长期无漂移。

实机验收仍需用户同意后进行：Thor 的应用捕获权限、游戏声是否正常、设备外放是否保留、单双屏启停、约三分钟漂移、音画启动偏移、USB 断线与文件恢复。遵循用户「先完成离线开发」选择，本批没有执行 `-Live`。

## 离线证据

`tools/test-capture-tool.ps1 -Stream` 包含协议/时间戳损坏检查、模拟设备 socket 的合成 440 Hz 声音、真实 FFmpeg AAC 合成与非静音样本解码、H.264 数据不变、双屏声音不翻倍、合成失败原片保持、捕获拒绝/断开、内置播放器暂停/跳转/关闭。声音播放调度使用测试输出验证；另以全零 PCM 验证本机真实 waveOut 暂停/恢复，未播放测试音给用户。

回归输出：`evidence/audio-regression.txt`；界面：`evidence/ui-check/window.png`；交付：`evidence/audio-delivery.json`。合成数据位于 `evidence/thor-capture-tests/audio-*`，不是实机录制。

## 第三方组件

使用未修改的官方 scrcpy-server v3.3.4，Apache-2.0。来源、校验、许可证见 `third-party/scrcpy/NOTICE.md`、`LICENSE` 与 `SHA256SUMS.txt`。构建脚本将固定组件和许可说明复制到输出目录；运行时再次校验固定哈希。未分发 scrcpy 桌面客户端或其 FFmpeg/SDL。公开发布前仍需完成项目自身许可、依赖交付与实际设备矩阵。
