# 录屏期间取景（2026-09-27）

单屏/双屏录制开始后自动显示持续更新的画面，不必先开启普通实时预览。第二行按钮变为「暂停取景」，暂停只停止显示采集，录像继续；「恢复取景」可再次开启。取景遵守「预览设置」的屏幕选择、尺寸与电脑显示上限，原生PNG选择也保留。

## 当前实现与范围

普通预览使用H.264视频流；录屏期间释放普通预览编码器，使用快速原始像素连续截图（不支持时回退PNG），每次并行采集所选屏幕，完成后仅保留当前画面。它不会再开启额外的screenrecord编码器。双屏录像仍使用原来的两路原生分辨率、8Mbps、最长180秒MP4录制与独立进程停止/下载流程。

连续截图的帧率通常低于视频流：界面显示取景采集周期估计fps，不能把它称为高帧率的共享视频流。此批次解决录屏时画面冻结、可暂停/恢复、异常隔离与状态衔接；没有声称解决录屏时低延迟视频预览。P3-6的带时间戳共享采集后端仍待研究与实机验证。USB设备是否允许screenrecord同时screencap、实际刷新率与对录制的影响均未验收。

## 状态与数据保护

- 设备依然处于录制忙碌状态，截图、设备切换和预览参数修改保持禁用；只对录屏取景开放忙碌刷新分支。
- 自动锁定图库，图库自动刷新不覆盖录屏画面，原片保存后再恢复选中素材或之前的普通预览意图。
- 按键反馈仍持续读取、录入CSV；动画独立调度，不把取景帧或鼠标演示写入视频/时间线。
- 取景失败仅暂停取景、显示原因并提供恢复按钮，不触发录像停止。录像故障仍由原录制会话处理。
- 暂停、结束录制使用generation拒绝迟到结果。结束后等在途截图完成，再解除忙碌，防止旧取景覆盖播放器或恢复的视频流。
- 不下载额外视频、修改用户素材、启动第三/第四路编码器、结束用户进程；不增加新的运行依赖。
