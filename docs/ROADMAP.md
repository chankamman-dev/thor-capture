## 1. 产品目标与边界

让 Thor 用户在电脑上稳定地预览双屏、截图、录屏、管理素材，并可选择导出带实机外壳和操作反馈的图片或视频。优先解决双屏采集、预览延迟、操作可靠性与素材管理，保持现有实机外观。

- 核心流程：连接设备 → 选择上下屏或双屏 → 预览/采集 → 图库检查 → 选择原片或带壳导出。
- 十字键、ABXY、摇杆、固定灯环和反射共享渲染代码；预览、图片和视频不能各自做一套外观。
- 原片始终保留。裁剪、标注、合成和同步校正生成新文件；导入、重命名、移动和删除必须处理同组文件与附属数据。
- 支持无设备浏览图库、无 FFmpeg 截图及兼容预览、无输入权限仅显示画面。降级原因必须可见。
- 不默认提权、不安装设备端常驻程序、不注入按键、不上传截图或操作记录，不加入广告或自动遥测。
- 不包括游戏 Mod、其他项目的 Android 伴侣功能、云账号或素材社区。暂不引入通用插件框架、数据库服务器或 UI 框架重写。

### 2.1 本阶段技术选择

- 保持 WinForms、C# 5、现有程序集和单 EXE 构建链，先解决职责与生命周期。新增强制 NuGet/运行时依赖需另立技术决策，不夹带在重构中。
- ADB 为设备采集依赖；FFmpeg 为流解码/合成依赖。缺失时显示可用功能和禁用原因。
- 保留绿色版，增加 EXE 目录不可写时的用户数据目录方案，不强迫管理员运行。
- 编译器路径 `v4.0.30319` 不等于应支持旧 Framework 4.0。公开版建议 Windows 11 + .NET Framework 4.8 为首批测试基线，最低系统/架构以干净机器验证后确认，不承诺全部 Windows。[Framework 生命周期](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-net-framework)、[系统与运行时依赖](https://learn.microsoft.com/en-us/dotnet/framework/install/versions-and-dependencies)。
- 首发推荐不捆绑 ADB/FFmpeg，提供检测与官方获取说明；未来捆绑前完成 P7-2 逐包授权审查。

## 3. 目标框架与模块职责

以下是迁移目标，不表示目录已存在。逐模块迁移，旧入口暂留适配层，避免一次搬完再验证。

```text
src/
  App/            启动、版本、数据路径、状态、任务协调、日志、异常边界
  Infrastructure/ 进程、ADB/FFmpeg探测、设置、原子文件、时钟
  Devices/        设备发现、显示信息、能力探测、连接配置
  Capture/        截图批次、单/双屏录制、恢复任务
  Preview/        视频/截图源、帧邮箱、统计、恢复与降级
  Input/          节点、映射、校准、状态与时间线
  Media/          媒体ID、组与元数据、索引、缩略图、文件事务
  Export/         图片/视频/GIF导出计划、进度、取消
  Rendering/      DeviceArt、Stick3D、Dpad3D、LampLight与公共场景
  UI/             窗口、图库控件、主题、对话框、提示
tests/            按行为分组，实机测试独立入口
tools/            构建、离线回归、渲染、打包、发布审查
docs/             使用、架构、兼容性、隐私、安全、贡献与计划
```

| 边界 | 应负责 | 不应负责 |
|---|---|---|
| ProcessRunner / IAdbClient | 参数、输出上限、超时、取消、退出码、拥有进程回收 | 弹窗、选设备、修改 UI |
| DeviceService | 发现、能力、设备快照 | 把全局 serial 偷传给运行任务 |
| Capture / RecordingService | 固定快照、组级结果、可恢复失败 | 图库布局、控件、无差别停止进程 |
| Preview / InputService | 有界管道、时间戳、统计、断流事件 | 写窗口布尔标记、跨线程绘图 |
| MediaRepository | ID、附属数据、缓存、增量索引、事务 | 运行编码器、自动删除相似图片 |
| ExportService | 不可变计划、逐项结果、进度、取消 | 覆盖原片、读取可变全局外壳设置 |
| MainForm / Presenter | 用户命令、状态投影、布局、提示、UI调度 | shell命令、WaitForExit、整库扫描 |

用少量可注入接口（进程、设备、文件、时钟、帧源）支撑故障测试，不引入复杂容器。服务返回类型化结果：成功、取消、不支持、断线、超时、文件失败；本地日志保留原因，UI 给中文恢复操作。

### 3.1 状态与并发规则

`AppState` 分开连接、设备操作、预览、输入和本地任务；`OperationGate` 发放资源租约，结束/失败/取消在 finally 释放。任务绑定 serial、display ID、generation、job ID，拒绝过期结果回写。

| 操作 | 初期资源规则 | 完成、失败或取消后的行为 |
|---|---|---|
| 发现/探测 | 与同设备采集互斥，不改变运行任务快照 | 能力结果不覆盖新选择 |
| 截图/开始录屏 | 先释放两路预览编码器并等清理；截图与录屏初期互斥 | 操作结束按用户意图恢复预览 |
| 停止/恢复录屏 | 停止始终可用，只操作本任务进程 | 成功原片保留，失败轨道有恢复入口 |
| 输入监听 | 有权限可与采集共存，独立取消 | 断线清空按压，避免卡键 |
| 本地图片导出/浏览 | 可与采集并行；文件组读写事务互斥 | 单项错误不破坏其他组或原片 |
| 本地视频合成 | 默认一个重任务、限制队列；预览按预算降载 | 取消只结束拥有进程，恢复意图保留 |
| 切设备/关闭 | 不强换进行中的设备；停止→保存/留恢复线索→清理 | 有界等待，提示未完成；不killall或杀其他程序 |

录制同时预览、单轨失败后另轨继续、设备截图并行等能力，用实测档案逐步放开，不能只改标志就宣称支持。180 秒续流的中断必须显示和记录。

### 3.2 媒体与时间模型

版本化 `CaptureBatch` / `MediaItem` 含 batchId、mediaId、屏幕角色、来源、原片/派生关系、尺寸/时长、创建时间、轨道结果、外壳快照、同步校正。索引可重建，不能成为素材唯一来源。

- 兼容旧文件名、`.thor-meta.txt`、`.input.csv`。首次只建索引，不批量改名；迁移先备份，保留未知字段。
- 区分设备事件时间、电脑单调时钟接收时间、发起/确认时间、视频媒体时间；标注估算与校准。接收时间不能冒充按下时间。
- 双屏导出保存各轨/输入偏移及结尾策略：较短片结束，或保留较长片并冻结/留空另一屏。
- 同卷临时文件→校验→替换；元数据失败不影响发现原片。文件组改名/移动/删除有计划预览、冲突检查和恢复记录。
- 公开诊断默认无完整 serial、用户名路径、应用列表；主动导出原始输入也说明内容。

## 6. 验收矩阵与性能证据

| 维度 | 必测场景 | 通过标准与产物 |
|---|---|---|
| 构建 | 干净源码、无ADB/FFmpeg、标准用户 | 可编译、缺依赖可解释、commit/工具/哈希 |
| 生命周期 | 超时、大输出、启动失败、连续启停、关闭断线 | 有界退出、可恢复、只清理拥有进程、无伪成功 |
| 数据安全 | 同名、满盘、只读、部分下载、坏元数据、事务中断 | 原片保留、可恢复、组对应、迁移备份 |
| 实机采集 | 各屏、拒第二编码器、时限边界 | 内容尺寸正确、完整解码、逐轨结果/恢复 |
| 输入/同步 | 全键轴/斜向/L3R3、拒权限、断线、长片漂移 | 映射/松开正确、未知能力明确、实测校正 |
| 预览 | 动态/静态双屏、180秒、30分钟、USB/无线分开 | 接收绘制分开、延迟方法、资源无持续增长 |
| 视觉 | 四配色、灯开关/亮度、摇杆偏转按压、十字斜向、透明 | 固定灯环、3D厚度光照、预览/图片/视频一致 |
| 桌面 | 100–200%DPI、小窗口、第二实例、键盘、只读目录 | 可达/可读、不截断、路径可写、无重复作业 |
| 图库 | 100/1,000/10,000冷热、通知溢出、坏素材 | 渐进首屏、资源有界、索引重建、选择保留 |
| 发布 | 授权/历史扫描、包allowlist、clean clone/解压/升级回退 | 许可清楚、无私人资料、源码包对应、文档可照做 |

每次证据绑定当前候选/环境：时间、commit或工作区清单、EXE哈希、命令、结果/跳过、依赖版本/条件。原始实机文件默认只放本地evidence，公开脱敏摘要或授权样例。内存区分缓存预热与泄漏，不能只用起止两点证明。
