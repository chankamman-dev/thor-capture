# 版本、兼容与维护规则（提案）

遵循 [Semantic Versioning](https://semver.org/)，建议首个候选 `0.1.0-beta.1`，后续 `beta.2`、`rc.1` 与正式 `0.1.0` 分开，不给尚未公开版本回填发布日期。源码版本、EXE 内版本和候选 manifest 必须由 Track A 同一来源生成；本包没有改程序集版本。

应用版本与设置/媒体/输入 schema 各自编号。升级读取旧格式，保留原始媒体和升级前配置；写新格式时明确最低回退版本，不承诺未知的跨版本互操作。兼容性改变记入 CHANGELOG 的 Compatibility / Migration；仅修复不改变数据行为时 patch，增加兼容功能用 minor，1.0 后破坏公开接口/格式用 major。0.x 也必须说明破坏性变化。

CHANGELOG 每版记录 Added、Changed、Fixed、Compatibility / Migration、Known limitations / Verification，提供实际依赖、测试边界、升级/回退和原片恢复方式。冻结后变更代码即重新构建、验证受影响项并更新哈希，不能沿用旧候选报告。

| 等级 | 范围 | 发布处理 |
|---|---|---|
| 阻塞 | 数据损坏、错误清理他人进程、泄漏、不能停止录制 | 阻止发布；已发包先评估撤下/警示与恢复，优先修复 |
| 高 | 核心截图/录屏/回看失败，无法可靠降级 | 默认阻止受影响能力声明，必要时关闭实验能力 |
| 普通 | 有明确绕过的非破坏性问题 | 发布说明与有证据的后续安排 |
| 外观/建议 | 不影响数据、安全的细节 | 按体验与成本排序 |

支持矩阵必须绑定实际构建哈希与测试固件/Windows/连接/DPI，合成流不证明双屏编码器、声音权限或端到端延迟。1.0 要完成 ROADMAP R3、至少一次公开反馈修复及紧急回退演练；实验声音/长录屏/共享后端未可靠验收则延期或明确实验。

维护者身份、支持窗口、安全通道及公开反馈渠道待确认，不承诺响应期限、长期 SLA、自动更新或代码签名。可以先交付候选与证据，公开动作由所有者最后批准。
